# Owner Edits, Batch 2: Quick Fixes and Layout (Plan 8) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Apply the owner's second batch of small fixes and layout changes. The larger features (strength-log redesign, three-ring layout, workout check-off, recovery-change history, user-added sources, lab screenshot upload, new logo) are Plan 9.

**Spec:** the owner's 2026-10-23 edit list and answers in chat, plus `docs/superpowers/specs/2026-10-22-visual-redesign-design.md` for the visual rules.

## Global Constraints

- **Rules from Plans 6–7 still apply:**
  - Theme tokens only, no emoji, Title Case for titles and labels.
  - 375 px with no sideways scroll, and tap targets of at least 44 px.
  - Every number comes from `RULES` or is a named display constant.
- **Privacy:**
  - The public repo holds no owner health details.
  - The pain side is a DB setting. Code never assumes "left".
- **Migrations:** they are additive and nullable, and are applied to Neon before the deploy that reads them.
- **Behavior:** existing data and actions are unchanged unless the edit asks for a change.

## Review Focus

1. **A date or time input on iPhone Safari at 375 px.** Expected: the field stays inside its card, in every form.
2. **The weekly box on a Tuesday after VO2 max was already saved Monday.** Expected: it reopens Tuesday and Sunday until a value is saved that day, and otherwise stays collapsed with Re-enter.
3. **Opening `/plan/library#rule.id` from a Why link while the Library streams in.** Expected: the page lands on that rule, even after filters are applied.
4. **Today for a past date.** Expected:
   - No WHOOP sync, and nothing is written (no plan adaptation for a past day).
   - That day's stored recovery, sleep, strain and food show.
   - A future date is refused.
5. **Pain Side unset vs set.** Expected: unset shows the side picker; set hides it and saves that side.

### Task 2: Inputs inside their frames

- **Fix in `globals.css`:**
  - `input`, `select` and `textarea` get `max-width: 100%` and `min-width: 0`.
  - `input[type="date"]` and `input[type="time"]` get `-webkit-appearance: none; appearance: none; display: block; width: 100%;`.
  - iOS Safari gives these a fixed intrinsic width, which is why they overflow on the left.
- **Check every form CSS module:** grid cells use `minmax(0, 1fr)`.
- **Test:** a CSS test asserts that the global rule exists for date and time inputs.
- **Manual:** curl every form page and confirm 200.
- Commit: `fix(ui): keep date and time inputs inside their cards`.

### Task 4: Log, collapsing boxes and WHOOP Add Details

- **Weight box:** when today has a weigh-in, show "Logged {lb} lb today" with a small "Re-enter" button that opens the form. Otherwise show the form.
- **Weekly box:**
  - Collapsed, showing the saved VO2 max and WHOOP Age with Re-enter, when this week's row exists.
  - Open when there's no row, or when today is Tuesday or Sunday and the row wasn't updated today.
  - Pure helper `weeklyBoxOpen(row: { updatedLocalDate: string } | null, today: string): boolean`.
- **WHOOP workouts:**
  - The Log hub lists the last 7 days' WHOOP swim, bike and run workouts that aren't linked to an app cardio entry, each with "Add Details".
  - "Add Details" links to `/log/cardio?whoop=<id>`. The cardio form pre-fills the kind, start time and duration from that workout.
  - Saving it creates the cardio entry linked to that WHOOP workout, using the existing linking.
- **Tests:**
  - `weeklyBoxOpen`: no row is open; a Monday save shown on a Tuesday is open; a Tuesday save on the same Tuesday is collapsed; a Wednesday shows collapsed.
  - `unlinkedWhoopCardio(db, now, tz)` returns only unlinked swim, bike and run workouts from the last 7 days.
  - The cardio pre-fill parser handles an unknown id (no pre-fill).
- Commit: `feat(log): collapsing weight and weekly boxes; add details to WHOOP workouts`.

### Task 5: Library filters and direct Why links

- **Filters:**
  - Area chips (All plus each area) and evidence chips (All plus each level).
  - Driven by the query params `?area=&evidence=`, as server-rendered links. A rule that doesn't match is hidden.
  - Pure `filterRules(rules, area, evidence)`.
- **Anchors:**
  - A small client `ScrollToHash` re-scrolls to `location.hash` after the streamed content mounts.
  - Filters keep the hash; a hashed rule is always shown even when filtered out.
  - All Why links use `/plan/library#<ruleId>`; audit the sweat test page and the others.
- **Tests:** `filterRules` combinations, and an unknown area means All.
- Commit: `feat(plan): library filters; why links land on the rule`.

### Task 9: Past days on Today

- **Date navigation:**
  - `/?date=YYYY-MM-DD` with prev/next arrows. The next arrow is hidden on today, and a future date redirects to today.
  - For a past date: no `ensureFresh`. Show that day's recovery, sleep, strain, HRV and RHR via `getTodaySummary(db, endOfLocalDay(date), tz)`, plus `getDayNutrition(db, date, …)` food.
  - The training card reads stored sessions only, through a new read-only `storedDaySessions(db, date)`. It never calls `getDayPlan` for a past date.
- **Tests:**
  - `parseTodayDate(raw, today)` refuses future and junk dates.
  - `storedDaySessions` returns that day's rows without writing anything (the recommendation log row count is unchanged).
- Commit: `feat(today): view past days`.
