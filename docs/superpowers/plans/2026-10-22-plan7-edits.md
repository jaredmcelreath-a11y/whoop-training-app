## Global Constraints

- **Everything from Plan 6 still applies:**
  - Colors only as theme tokens, no emoji, Title Case for titles.
  - 375 px with no sideways scroll, tap targets of at least 44 px.
  - No behavior changes beyond these edits.
  - Public repo, with no owner data in tests or docs. Never push without the owner's OK.
- **Evidence policy (§9):**
  - Every new number lives in `RULES` with verified citations, each citation carrying `role` `supports` or `context`.
  - The evidence level is the strongest supporting citation.
  - Galpin counts as expert context and Bryan Johnson as n-of-1 context, never as primary support.
  - Each rule has a caveat, and the numbers-in-text test must pass.
  - The app never states a dose beyond what a sourced rule states. Each note says "not medical advice; check with your doctor or a registered dietitian".
- **Migration:** add `0005` for `plan_settings.wake_time text NULL`. It must be applied to Neon **before** the code that reads it deploys.

## Review Focus

1. **No recovery yet today** (before WHOOP scores), or a WHOOP outage.
   - Expected: every page uses the neutral accent glow. No page errors, and none waits on WHOOP.
2. **A workout recorded by both WHOOP and the app**, or one that doesn't match the planned sport.
   - Expected: it appears once. A matching planned session shows as done at its real start time; anything else shows as its own item.
3. **Wake time left blank.**
   - Expected: the current behavior (the first window minus 45 min).
   - When the wake time is after the first window's start, the timeline still orders correctly.
4. **A supplement name with a typo or different wording** ("Colagen", "fish oil", "Mg glycinate", "D3+K2").
   - Expected: it still gets the right note. An unknown name gets no invented note.
5. **The nutrient page with no reference profile, or no food data.**
   - Expected: the targets show "—" with a link to set up the profile. No zeros pass for real values.

### Task 5: Real workouts on the Day timeline

**Files:**
- Modify: `src/lib/engine/day-timeline.ts` (an optional `sport` on session items) and its test
- Modify: `src/lib/nutrition/day-view.ts` and its test, and `src/app/day/page.tsx`

**Interfaces:**
- **Produces:** `actualWorkouts(db, date, tz): Promise<{ startHHMM: string; sport: "swim" | "bike" | "run" | "strength" | null; title: string; durationMin: number; source: "app" | "whoop" }[]>`
  - Sources:
    - finished app strength sessions;
    - app cardio entries;
    - WHOOP workouts on that local date that aren't linked to an app entry. Use the existing link columns, and skip generic "activity".
- **Produces:** `mergeActual(items: TimelineItem[], actual): TimelineItem[]`
  - An actual workout whose sport matches a planned session item that day (the first unmatched one) moves that item to the real start, adds "Done at HH:MM" to its detail, and keeps its ruleIds.
  - Otherwise it inserts a new `session` item at the real start, with the title through `titleCase`, the detail "Logged · N min" (or "From WHOOP · N min"), and no ruleIds.
  - The result is sorted with the same day-order rule as the timeline. A collision moves by +5 min.

- [ ] **Step 1: Failing tests**
  - **`mergeActual` (pure):**
    - A run matching a planned run moves that run, with no duplicate.
    - A WHOOP weightlifting workout with no planned lift inserts a new item.
    - Two runs pair with two planned runs in order.
    - A workout with an unknown sport inserts an item.
  - **`actualWorkouts` (DB):** a WHOOP workout linked to an app cardio entry appears once, as the app entry.
- [ ] **Step 2:** Implement, and wire it into the Day page.
